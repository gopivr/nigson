# Section 42 load fixture and evidence

The section 42 workload is 100 simultaneous sessions, 20 catalogue requests/second, and 2 checkout flows/second for 30 minutes against 10,000 products and 20,000 SKUs. Each accepted run records p50/p95/p99, throughput, errors, CPU/memory, JDBC pool waits, query plans, queue age and provider time split. Cache-disabled execution is the correctness baseline. Checkout uses isolated synthetic identities, carts and approved fixture inventory; production/customer data is never a load fixture.

`scripts/load/section42.py` is the executable fixture. It uses exactly 100 distinct session fixtures, schedules one catalogue read every five seconds per session (20 RPS aggregate), and submits checkout flows at two arrivals/second for 30 minutes. Each checkout creates a fresh cart, adds one prequalified SKU, obtains the FedEx rate, creates a checkout quote and starts the order/payment flow. The client stops on any failed request or uncertain HTTP 202 checkout outcome; it never retries a checkout. Output contains only per-route aggregate request/error counts and latency percentiles. It rejects non-loopback HTTP/public hosts, redirects, oversized responses, fixtures outside ignored `.build/load`, non-private fixture permissions, duplicate sessions and malformed identifiers.

Prepare the 100 session objects from a dedicated synthetic test identity set. Each object has exactly `cookie`, `csrf`, `marketCode`, `marketId`, `addressId`, and `skuId`. Store the JSON at `.build/load/section42-fixture.json` with mode `0600`; do not check in the file or print its contents. The selected catalogue must contain 10,000 products/20,000 SKUs, and the selected SKU must have reviewed synthetic inventory sufficient for the run. Both commerce and provider modes must be approved for the test environment, with payment/carrier adapters using the local stateful mocks.

Run with `NIGSON_LOAD_TARGET=http://127.0.0.1:<port>` for local test or an approved private `https://<service>.internal` target for an isolated stage, and `NIGSON_LOAD_FIXTURE=.build/load/section42-fixture.json python3 scripts/load/section42.py`. Do not run against a public or production endpoint. The script records application latencies/errors but does not collect host/container CPU, memory, DB pool waits, query plans, queue age or provider time split; capture those from the approved telemetry during the same window. No run has been made because the required application target, fixture identities/data and stage approval are not present.

The run creates synthetic orders and payment intents and consumes fixture inventory; it is not read-only. A test-only database/identity target, provider mocks and reviewed cleanup procedure are mandatory before execution.
