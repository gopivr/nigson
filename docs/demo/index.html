Start the demo

From the repository root, copy the local template once and start the core services:

cp .env.example .env
make local-config-check
make local-up
make migrate ENV=local
make seed ENV=local FIXTURE_PROFILE=foundation
make run-core
python3 scripts/local/demo_server.py

Open http://localhost:8090. The local server serves this static page and forwards only to loopback Commerce, Experience and AI ports. The private Integration API is intentionally not exposed. Use the “Sign in” button for the real Keycloak BFF flow when the local security profile is configured; fixture accounts are documented in infrastructure/docker/keycloak/nigson-local-realm.json and use the fixture password mock-local-user.

The standard Compose profile intentionally leaves domain security inputs unset. Health checks work, while protected business routes and BFF login stay closed until those inputs are configured. The demo server does not bypass authorization or create tokens. Never copy local mock credentials into a live provider configuration.

Optional AI profile

The AI service is not started by the core profile. For BP5 exploration, set SCHEMA_RELEASE=BP5, then run the optional AI commands in the local application guide. Conversation creation needs locally managed anonymous and checkpoint keys, TTL settings, locale and allowed market. A message also needs an approved policy and prompt revision in the AI schema. The local provider is deterministic, but no policy, model, budget or retention values are seeded by this demo. Staff policy/model activation routes remain gated by real approval inputs.

Request behavior

API calls use JSON request bodies, optional idempotency/version headers, and a correlation ID. Commerce BFF cookies pass through only to Commerce. The page does not mint identity assertions or bypass service authorization. It shows HTTP errors and safe problem responses returned by the backend, and offers binary downloads when an endpoint returns a file.
