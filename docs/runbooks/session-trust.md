# BFF session and private trust operations

SEC-001 supplies security use cases and filters. COM-SESSI-001 implements API-001–004 public DTO/controllers/provisioning; COM-AUTHO-001 implements role assignment commands and last-admin protection; see `staff-authorization.md`. Framework authentication fixation rotation is explicitly disabled: JdbcSessionTrust rotates once after OIDC code acceptance, while ordinary trusted requests preserve that cookie. Unimplemented public business routes deny by default. Identity roles never replace commerce role assignments. Session/protocol records are not persistence entities or browser response DTOs.

Enable `NIGSON_SECURITY_ENABLED=true` only with explicit environment configuration. Commerce requires exact realm `NIGSON_OIDC_ISSUER`, `NIGSON_BFF_CLIENT_SECRET`, `/bff/callback` absolute `NIGSON_BFF_CALLBACK`, comma-separated relative `NIGSON_BFF_RETURN_PATHS`, exact `NIGSON_BFF_ALLOWED_ORIGINS`, `NIGSON_COMMERCE_WORKLOAD_SECRET`, `NIGSON_PRODUCT_PHASE`, private socket-peer `NIGSON_PRIVATE_PEER_CIDRS`, AWS region, actor KMS key ARN/active key ID/public DER key and pinned `NIGSON_ACTOR_PUBLIC_KEYS` JSON map. Experience/integration require their issuer, phase, peer CIDRs and actor public key map. Production inputs have no fabricated domain/account/key values. Existing foundation-only startup guards remain until domain/deployment tasks provide the full production application configuration; this task does not release BP1.

Session encryption uses a separate symmetric KMS key, not the asymmetric actor signing key. The named provisioning operator generates an AES256 data key with context `purpose=nigson-commerce-session, revision=<approved key revision>` and stores only its wrapped ciphertext in the environment's secret reference. Supply `NIGSON_SESSION_KMS_KEY`, `NIGSON_SESSION_KEY_REVISION`, `NIGSON_SESSION_WRAPPED_KEY`; optional `NIGSON_SESSION_PREVIOUS_WRAPPED_KEYS` maps at most two prior revisions to wrapped ciphertexts under that key. Runtime may unwrap at startup, never generate/encrypt/manage keys. Local/test KMS configuration requires an explicit loopback/localstack `NIGSON_KMS_LOCAL_ENDPOINT` and uses dummy credentials exclusively there; other environments use ECS container task credentials and reject endpoint overrides. Raw local session keys are an explicit `NIGSON_SESSION_LOCAL_KEY` base64 exception only for local/test and cannot coexist with KMS inputs. No private actor key is loaded into the production process. Actor KMS requests use ECDSA_SHA_256/DIGEST and verify the returned DER signature against the pinned P-256 public key before releasing a compact assertion.

No identity HTTP runs under an active owner transaction. Startup unwraps keys before the session codec is used; typed attributes use local AES256-GCM with fresh nonce, authenticated version/key/type metadata and no arbitrary Java deserialization. Session table names remain `commerce.spring_session` and `_attributes`, initialized only by existing Liquibase. No migration bytes or owner boundaries changed.

Rotate session data key revisions with bounded old-key overlap for the maximum 12h session lifetime, then remove old wrapped keys. Keep both actor public keys deployed at all receivers before changing the signer; retain the old public key for at least the 60s assertion lifetime and applicable clock tolerance. Restore JDBC sessions only with the corresponding wrapped-key revisions available; a missing key or altered ciphertext fails closed. Never silently fall back to a local key after KMS failure. KMS administrative access remains an infrastructure privilege boundary.

Pending login expires in 5m. `consume` deletes the exact encrypted pending attribute once before code HTTP; wrong state does not consume another login, callback replay fails, and failed/uncertain exchange requires a fresh login. Successful authentication atomically deletes the old JDBC row/attributes and creates a new session ID/primary key. The provider token tuple is signature/issuer/audience/client/at_hash checked; authorization-code exchange additionally requires exact nonce (refresh ID tokens may omit it) and never sent to JavaScript. Idle lifetime is 30m; absolute lifetime is 12h and cannot be extended by refresh. The refresh claim persists REFRESHING before provider HTTP, so concurrent refresh has one winner; crash/uncertainty fails closed and requires fresh login. Never replay a potentially consumed refresh token blindly. Logout deletes local JDBC state before one provider logout attempt; surface failure rather than inventing provider revocation success. Role/entitlement changes must call `revokeSubject` in their owner command transaction alongside audit; rollback preserves both assignment and sessions.

Cookies are host-only, Secure/HttpOnly/SameSite=Lax/Path=/ with `__Host-nigson-session`; only the explicit local HTTP profile uses `nigson-local-session`. CSRF is session-bound and checked before cookie mutations. Exact credentialed CORS rejects wildcard/suffix/null origins and unregistered preflight headers. Public bearer/actor headers are refused; private routes require a workload token and reject browser cookies/origin/query tokens. Private proof checks the socket peer, not X-Forwarded-For. Deploy private and public traffic with distinct security groups/listeners; public ALB must block `/internal/**`, including encoded/traversal variants. INFRA-001 must qualify the actual ALB/WAF/egress and endpoint configuration.

Keycloak's BFF AMR mapper emits authentication references; an explicit auth_time user-session-note mapper is required because custom scopes omit the default basic scope; the owned OTP execution config is `default.reference.value=otp`, `default.reference.maxAge=900`. Signed ID-token `amr` plus `auth_time` establishes the MFA instant. Refresh does not extend it. Staff role changes must also enforce the Keycloak authentication marker/session revocation procedure from the identity runbook; absence of proof denies recent-MFA operations. ADMIN is not FINANCE and never bypasses resource ownership or two-actor approvals. Organization context requires an active membership, active organization and the exact server-selected required entitlement; an arbitrary other active entitlement or requested organization UUID grants nothing. Commerce rechecks delegated party identity and intersects asserted roles with current assignments. Remote owner policy remains independently authoritative; previously minted delegation has an explicit bounded 60s lifetime, not an instantaneous global revocation guarantee.

The private wire contract is `contracts/security/actor-assertion.json`, with exact master workload bindings in `workload-scopes.json`. Assertions bind audience, operation, method, undecoded resource path, exact body SHA256, party/identity, optional approved organization, current roles/scopes, correlation and random jti. Owner DTO/object/organization checks and durable mutation idempotency still run after wire trust. Reads may replay; the proof is not a substitute for payment/order/inventory transaction rules. Never forward either proof or browser tokens to provider hosts or user/model-selected URLs.

Run `make security-check` for fresh native owner/race tests; `SEC_IDENTITY_CHECK=true make security-check UV=.build/uv-package/bin/uv` adds real optimized two-replica Keycloak, code/PKCE/MFA/JDBC/refresh/logout/workload and vendor restore checks. `make security-infra-check` runs backend-free locked init/validate/mock plans. `make cold-start UV=.build/uv-package/bin/uv` tests the complete isolated bootstrap surface. Only test-prefixed stacks are mutated; original nigson-local IDs/start times/mounts are compared before/after. Provider keys/dumps/raw vendor output stay ignored under `.build/`. Genuine AWS IAM/KMS/ALB and activation qualification remains NOT_RUN until approved inputs exist.

Primary implementation references: [Spring Session JDBC serialization](https://docs.spring.io/spring-session/reference/configuration/jdbc.html), [Keycloak AMR mapper](https://raw.githubusercontent.com/keycloak/keycloak/26.8.0/services/src/main/java/org/keycloak/protocol/oidc/mappers/AmrProtocolMapper.java), [Keycloak authentication references](https://raw.githubusercontent.com/keycloak/keycloak/26.8.0/server-spi-private/src/main/java/org/keycloak/models/Constants.java), [AWS KMS condition keys](https://docs.aws.amazon.com/kms/latest/developerguide/conditions-kms.html), [AWS Sign](https://docs.aws.amazon.com/kms/latest/APIReference/API_Sign.html).

Compatibility note: existing opaque Java-serialized framework attributes are not deserialized by the new codec. Deployment must require reauthentication for those sessions; preserve records until the approved cleanup procedure, rather than enabling unsafe fallback deserialization. Current implementation has no previously released BFF token session format. Keycloak realm/client policy revision must migrate the prior tooling callback to `/bff/callback` and add explicit AMR/auth_time mappers before activating the security foundation. These configuration changes are applied only to fresh isolated qualification realms here.
