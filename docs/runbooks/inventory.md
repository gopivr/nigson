# Commerce stock operations

API-170 creates an explicitly supplied unique stock location with zero available stock. It inserts no balance. Location priority and actual warehouse facts remain approved configuration for fulfillment; no arbitrary first-row selection. API-045 is a current OPERATIONS, no-store bounded stock page; available=onHand-reserved-allocated. Every value is a decimal string at immutable SKU scale. The page is a diagnostic snapshot, never an authorization to sell.

API-046 requires current OPERATIONS/issuer/subject with no organization, BFF session CSRF, Idempotency-Key and quoted balance If-Match. An absent balance starts at version0 within the explicit adjustment; successful first adjustment returns version1. Locations/SKUs must be active/nondeleted. A reduction cannot cross reserved+allocated and an increase cannot overflow numeric20,3. Stable actor/API/key movement identity, balance version, audit, EVT-005 and header acknowledgement commit in one transaction. Replay requires current authority and preserves original response; changed input/key version conflicts. No stock is fabricated by merely creating catalogue/location records.

Owned immutable movement reasons are protected operational evidence and do not appear in DTOs/audit or logs. Do not purge movement or local command journal keys when their generic expiry metadata elapses; no purge job or retention policy was introduced. Runtime roles cannot update/delete inventory movements. Reconcile sums of movement deltas to each balance using owner-scoped operator tooling; never edit a balance to hide drift. Every legitimate balance starts at zero and is funded by an explicit adjustment.

StockLedger is a local application port, with no HTTP route. The caller authorizes checkout/verified settlement/cancellation/fulfillment, starts its short commerce transaction, and supplies a stable business command UUID, causative verified Party UUID or server-owned scheduler subject, correlation and immutable order lines. Never bind actor or movement keys from browser fields. Calls reject outside a transaction; there is no internal transaction creation, provider call or blind retry. The adapter locks order, references and balance UUIDs in consistent PostgreSQL UUID order, with bounded waits/queries. Caller must use this port's locking sequence, rather than acquiring balances in a different order.

RESERVE covers the complete owned order's SKU quantities, requires published active products/active locations and fits current available stock. All lines fail together. RELEASE acts only on RESERVED quantities for a cancelled order; the owning expiry/cancellation flow first resolves provider uncertainty or applies its approved grace. This adapter never assumes an expired payment is failed. SETTLE requires paid/unheld order plus an owned immutable settlement for a SUCCEEDED attempt with sufficient matching currency/mode. Payment owns actual provider/account verification. A pre-payment released reservation may be reserved again in PAYMENT_HOLD for verified late settlement if stock remains; an already allocated/dispatched/returned reservation cannot be reused this way.

DISPATCH subtracts onHand and allocated together, checks paid/unheld state, immutable order-line SKU/quantity and cumulative dispatch/cancellation bounds. Partial dispatch preserves ALLOCATED until all units are accounted. The fulfillment caller must qualify booking/labels/physical dispatch before this local call; this stock adapter cannot qualify a carrier itself. Physical return requires an explicit protected receipt and cannot exceed dispatched quantity minus previous physical returns. UNSHIPPED_CANCEL explicitly reverses eligible allocated units during authorized cancellation/refund; onHand remains unchanged for goods still on hand. A full unshipped cancellation is RELEASED, never falsely DISPATCHED. Changing an order's refund status alone changes no stock. Return dedup is stable command+line; kind/body changes409.

Audit actor kind distinguishes verified Party UUIDs from server-owned system subjects. Audit/outbox/state changes roll back together, including multi-line failure. Local command journals cache the original bounded StockDTO list; exact UUID/body replay cannot duplicate movements. Failed or uncertain provider work is addressed by its owning payment/fulfillment reconciliation task, never a new inventory command key.

Use `make inventory-check ENV=test` for isolated PostgreSQL, actual BFF cookie/CSRF/current-role/version/error checks, last-unit and reversed multi-balance races, atomic checkout rollback, allocation uncertainty/hold denial, partial dispatch/capped returns, ledger reconciliation and audit failure recovery. Synthetic unit/zero-charge order/mock merchant records are not approved initial stock, tax, prices or live provider evidence. Real checkout/payment/fulfillment orchestration and staging/load qualification remain their respective roadmap gates.

Metric nigson.inventory.movements is tagged only by the six compiled movement types and increments after commit. Replay/audit/stock rejection changes no counter. Production filtering rejects arbitrary movement types, IDs and other labels; the BFF acceptance verifies the actual registry rather than relying only on a simple test registry.
