# Public BFF session lifecycle

API-001–004 use the existing confidential Keycloak HTTP adapter and encrypted server-side PostgreSQL Spring Session records. Browser access/refresh/bearer tokens are denied. All session responses are no-store; provider tokens never appear in SessionDTO, cookies, redirects or audit values.

GET /bff/login accepts only one optional returnTo from NIGSON_BFF_RETURN_PATHS (default /account). It creates a five-minute pending state, nonce and PKCE S256 flow and writes a host-only Secure/HttpOnly/SameSite=Lax cookie. Explicit local HTTP uses the existing local-only exception. The owner transaction enforces 20 live pending flows per HMAC socket-IP fingerprint and 10000 globally across replicas. These engineering abuse bounds do not grant retention approval or trust forwarded client IP headers. Existing ingress/WAF release gates still apply.

GET /bff/callback accepts exactly one bounded code and state. It consumes state before HTTP, checks confidential code exchange, signed access/ID token issuer, audience, authorized client, subject, nonce and profile claims, provisions the exact issuer/subject Party, rotates the session and redirects to the stored allowlisted path. Failure or timeout invalidates the flow; begin a new login rather than retrying a code after possible acceptance. The production realm policy includes explicit signed email/email_verified/name ID-token mappers. Both local and optimized realms suppress extra issuer/session_state authorization-response parameters to honor the closed code/state callback contract. A single configured issuer, one-use flow binding and signed issuer/audience/nonce validation remain mandatory. The vendor harness verifies the exact callback query; upstream attribute names are declared in https://github.com/keycloak/keycloak/blob/main/server-spi-private/src/main/java/org/keycloak/protocol/oidc/OIDCConfigAttributes.java. Identity email updates never merge Parties or change user-edited display names.

GET /bff/session takes no query/body. Anonymous, expired or suspended mappings return the exact unauthenticated DTO. Active sessions return current commerce roles and active BP3 membership, current idle/absolute expiry and session CSRF. Near-expiry refresh is claimed by an optimistic CAS; no DB transaction spans provider HTTP, and uncertain refresh deletes local state instead of retrying a rotated token. Refresh preserves original login time/MFA and absolute TTL.

POST /bff/logout takes exactly {} and bound CSRF. Audit and local JDBC deletion commit before supported provider revocation HTTP. Successful revocation returns 204; upstream failure returns safe 503 with the local session deleted and cookie cleared. Audit/database failure rolls back deletion and stops provider HTTP. A client whose cookie was cleared can begin a new login. No domain event or arbitrary upstream route is introduced.

Audit SESSION_LOGIN/SESSION_LOGOUT stores a session resource UUID and version metadata with Party actor, never token/contact/nonce/verifier values. Shared platform route/status metrics, problem counters and correlation logs cover endpoint behavior; security lifecycle metrics count login/logout/denial. Pending login data uses existing encrypted session expiry; production approved cleanup/retention gates remain separate.

Qualification: JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-25.jdk/Contents/Home make session-check. Native local acceptance uses real signed HTTP token responses and a stateful loopback OIDC mock, plus isolated PostgreSQL and two actual Boot replicas. Genuine Keycloak qualification is a separate pinned local vendor identity-check and approved staging/live gate; mock success cannot establish live account metadata or production activation.
