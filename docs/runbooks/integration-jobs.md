# Staff integration jobs

API-163 lists a bounded, closed JobDTO page for current OPERATIONS. API-164 retries one job with current OPERATIONS, a verified BFF session, MFA within fifteen minutes, CSRF, quoted If-Match and an Idempotency-Key. ADMIN is not an implicit OPERATIONS grant. Organization contexts and browser bearer/delegated tokens are rejected. Commerce never reads integration SQL or provider payloads.

Set NIGSON_INTEGRATION_JOBS_ENABLED=true only with an explicitly approved NIGSON_INTEGRATION_BASE_URL. Disabled is the default and creates no retry intent. Local/test targets are explicit localhost/127.0.0.1/integration/integration-mock endpoints; dummy identity credentials stay local. Other environments require HTTPS to an explicitly supplied private DNS name ending `.internal`. No hostname/account/default credential is invented; approved internal DNS/certificate/connectivity are deployment inputs. Configured requests use only compiled /internal/v1/jobs and /internal/v1/jobs/{UUID}/retry routes. No redirects, arbitrary caller URLs, browser credential forwarding or automatic application retries. Connection timeout2s, request timeout5s, overall future deadline6s and response cap64KiB include a stalled response body.

The existing SEC-001 client-credentials provider validates actual Keycloak workload JWT issuer/audience/client/scope. Reads use jobs.read and omit actor assertions, as the exact API-140 registry requires. Retries use jobs.retry_WITH_SIGNED_STAFF with a fresh ES256 assertion produced by the pinned KMS signer. Assertions bind current actor, role, MFA, method, resource, exact body bytes and correlation. Signing/token/provider HTTP all happen outside database transactions.

API-164 uses a distinct owned idempotency operation API-164-PRIVATE-ACK. It hashes target UUID, expected version and closed reason input; raw reason is not retained in the command record or audit. The row UUID is the stable private Idempotency-Key. A short owned transaction checks current issuer/subject/active Party and OPERATIONS under a Party share lock, then commits CALLING intent/lease and QUEUE_REPLAY audit before HTTP. RUNNING response_body.outcome carries PREPARED/CALLING/UNKNOWN; no applied schema/state constraint is altered. This operation is never passed to generic executeLocal, which has different local-command recovery semantics. Do not delete UNKNOWN/RUNNING rows as expired cache.

Concurrent calls return409/Retry-After1. An acknowledged202 stores the closed DTO plus actual upstream ETag; matching replay avoids both signing and upstream calls but still checks current authority/MFA. A changed body/target/version with the original key returns409. Definitive compiled rejection is durably cached with a safe code. Uncertain response, timeout, malformed success or final audit failure retains CALLING/UNKNOWN. Reconcile by submitting the identical original browser key/body/version: commerce sends the same private command UUID, and integration's durable command ledger must acknowledge it without enqueueing a second job effect. This is command acknowledgement reconciliation; it is not permission to retry an UNKNOWN provider side effect. Integration owns the original business/provider key and must first reconcile provider UNKNOWN before eligibility for any provider call. No unregistered status endpoint or guessed job version is used.

Metrics nigson.provider.commands have bounded ACKNOWLEDGED/UNKNOWN outcomes. QUEUE_REPLAY audit uses operator UUID, job UUID, correlation and approved state/version fields; free reasons, credentials, assertions, provider messages and payloads are excluded. Upstream bodies must be closed DTOs; safe compiled problem codes are mapped without copying upstream detail. No-store applies to every staff result and problem.

Contract conflicts: API-163's generic prose says signed actor, while the exact API-140 permission and compiled registry use jobs.read and explicitly reject an actor. The specific registered read contract governs; signed staff is required for API-141 retries. JobDTO omits version although retries require If-Match. This implementation forwards an explicitly supplied expected version and returns the actual accepted ETag; it cannot provide initial per-job version discovery from the specified list DTO. Proposed future contract resolution: approve a version field on JobDTO across API-140/141/163/164, or a separate compiled versioned read endpoint. Neither change is silently introduced. Staff UI version discovery remains NOT_RUN/contract-dependent.

`make integration-jobs-check` executes isolated owner migrations, native persistence/races/audit rollback and real HTTP/KMS/JWT/MFA/CSRF qualification. Stateful worker mock acceptance is not a completed integration worker, staging release or live Paystack/FedEx/messaging qualification. INT-PROVI-001 and provider activation gates retain their own acceptance requirements.
