# Commerce files

API-111 creates an owned UPLOADING asset and file_transfer before signing a constrained five-minute HTTPS PUT. Current CONTENT_EDITOR, no organization context, exact issuer/subject/current role and purpose/resource checks apply. IMAGE <=5MiB JPEG/PNG/WebP; BROCHURE <=10MiB PDF; no browser SHIPPING_LABEL or private classification override. linkedResourceId resolves only an owned product/SKU. Detached assets are creator-only. Filenames are normalized display input and never enter object paths. Storage keys are `{env}/commerce/{purpose}/{assetUuid}/{revision}/{safeExtension}`; quarantine revision0/final revision1. Required signed headers bind content length/type/SHA256, owner/asset metadata, encryption and If-None-Match:*; upload cannot overwrite previously accepted bytes. Matching upload replay returns the original capability, which may have expired; it does not extend authorization or upload TTL.

API-112 requires expected asset version0 and matching declared checksum. Provider HEAD runs outside DB transactions and validates actual size/MIME/checksum/owner/encryption plus a non-null versioned object ID/ETag. The owned transaction stabilizes current editor access, locks Product before asset/transfer, rechecks version/state and atomically commits QUARANTINED/version1, pinned bytes, a unique scan-command ID, audit and EVT-025. That scan-command ID is the emitted event ID. A202 returns AssetDTO plus a Location at the download gate; the download remains denied until clean. The external scanner owns sniffing/decode/PDF/malware checks with the section26 budget; commerce never substitutes declared MIME for scanner acceptance.

API-132 is private and requires the compiled integration client/files.scan.write workload proof; browser cookies/actors cannot submit results. Callback commandId/checksum must match the persisted configured scan request, and first-completion If-Match is1. Closed callback hash binds result/scanner revision/reason; duplicate matching results have no second copy/state/audit effect, and contradictory/out-of-order terminal results409. Claim persists COPYING/hash/15-second lease before unlocked pinned-version, source-ETag conditional copy to the immutable final key. Destination If-None-Match:* prevents replacement. Final HEAD must match owned checksum/size/MIME/owner/encryption before CLEAN. CLEAN/REJECTED, audit and durable response commit together. Public business publication remains a separate catalogue transaction.

A timeout or crash after copy intent remains UNKNOWN/quarantined; an expired copy lease is treated as uncertain. Repeated same callback reconciles HEAD at the deterministic final key and never blindly issues another copy. If verified matching final bytes exist, outcome can finalize CLEAN. Missing/unavailable/conflicting final bytes retain uncertainty and503; no automatic recopy or outcome invention. Inspect the owned transfer and safe `nigson.files.transfer{outcome=UNKNOWN}` metric, preserved provider outcome and job identity before any separately authorized recovery decision. A final-audit failure also retains copy intent, allowing post-lease reconciliation without a second side effect. Rejected assets remain inaccessible. This increment performs no retention deletion; configured lifecycle/holds and real bucket retention approvals remain release inputs.

API-113 requires current CONTENT_EDITOR and related-resource/detached creator access, only CLEAN/PUBLISHED, and audits the grant before signing outside locks. Generated shipping labels require current OPERATIONS, a linked owned shipment and PRIVATE classification; labels never enter browser upload/catalogue/CDN paths. URLs expire60s and responses use no-store. No keys, binaries or cloud credentials appear in AssetDTO; scanner response url remains null until the separate public publication representation. All browser mutation requests need CSRF/Idempotency-Key; completion/callback need If-Match. Unknown fields/queries/bodies/duplicate headers are denied.

Storage activation is explicit NIGSON_FILES_ENABLED=true. Supply distinct approved NIGSON_S3_QUARANTINE_BUCKET/NIGSON_S3_PUBLIC_BUCKET/NIGSON_S3_PRIVATE_BUCKET, NIGSON_AWS_REGION and (outside local/test) an approved regional NIGSON_S3_KMS_KEY ARN. Production uses ECS container credentials, AWS endpoints, bounded SDK timeouts and one attempt; local endpoint/CA are forbidden. Local/test requires an explicit allowlisted HTTPS NIGSON_S3_LOCAL_ENDPOINT and optional explicit NIGSON_S3_LOCAL_CA; dummy credentials are bound exclusively to this target. Disabled storage throws FEATURE_DISABLED; no success/mock fallback. Missing/incompatible enabled configuration fails startup. Versioning/encryption/task IAM, origin access/CDN isolation and genuine scanner qualification are infrastructure/release gates, not inferred from mocks.

Run `ENV=test python3 scripts/files/verify.py` with pinned JDK and local Unix Docker. It starts isolated migrated PostgreSQL and a temporary TLS stateful S3 fixture that validates SigV4, checksum and conditional writes, stores versioned bytes, and exercises timeout before/after acceptance. Fixtures use dummy credentials and a known synthetic PNG. This qualifies commerce HTTP/storage/state/security behavior; the synthetic scan result is not real malware-scanner or live-cloud qualification. Full production scanner work remains integration/provider task scope. ADR-009 documents the additive owned transfer schema and populated rollback refusal.
