# FedEx delivery quote operation

API-181 is the customer cart delivery quote command. It requires an encrypted BFF session, current CUSTOMER authority, owned cart/address, CSRF, a stable Idempotency-Key and the quoted cart If-Match version. The only body fields are addressId and optional serviceCode; customers cannot supply a fee, account, origin, package weight or transport URL.

Commerce captures current approved NG market, destination and server packing in a short owned transaction. It releases locks before requesting private API-182 with a scoped Keycloak workload JWT and a KMS-signed actor assertion bound to exact body, route and correlation. Integration uses its configured FedEx account and OAuth adapter; the rate read never books a shipment. The exact single ACCOUNT rate must match the selected approved service and NGN. Missing eligibility, unsupported route, wrong currency, ambiguous rate or provider outage cannot produce an invented fee or manual fallback.

The private response body remains the closed carrier quote DTO. X-Nigson-Carrier-Mode is mandatory trusted owner metadata from the actual adapter: MOCK, SANDBOX (TEST transport) or LIVE. Commerce matches its qualified mode before binding the fee. Private command acknowledgement hashes include mode and approval identity. A mock fee cannot be relabelled as sandbox/live by changing source configuration or replaying a previous command.

Commerce then rechecks cart version, current ownership/organization, market approval, address hash and server package hash before atomically persisting carrier_quote and audit. Expiry is no more than five minutes and is clipped to current payment/carrier approval expiries. The provider snapshot pins the server shipper for future order/booking context. Existing valid quotes retain their fixed fee; checkout independently revalidates binding and expiry. Quote creation reserves no stock and does not initialize a payment. Matching successful source keys return the original acknowledgement without another HTTP/KMS call; current customer authority still applies.

Both boundaries are disabled by default. Integration requires NIGSON_CARRIER_ENABLED=true, NIGSON_SECURITY_ENABLED=true, FEDEX_MODE/BASE_URL/CLIENT_ID/CLIENT_SECRET/ACCOUNT_NUMBER and explicit NIGSON_CARRIER_SERVICES, NIGSON_CARRIER_DEFAULT_SERVICE, NIGSON_CARRIER_PICKUP_TYPE, NIGSON_CARRIER_APPROVAL and NIGSON_CARRIER_APPROVAL_UNTIL. Supported pickup policy values are DROPOFF_AT_FEDEX_LOCATION, USE_SCHEDULED_PICKUP and CONTACT_FEDEX_TO_SCHEDULE; selecting a value is an account/origin configuration decision, not a default route promise.

Commerce requires NIGSON_CARRIER_QUOTES_ENABLED=true, private security/workload/KMS configuration, NIGSON_INTEGRATION_BASE_URL, existing qualified pricing/fulfillment provider settings and NIGSON_CARRIER_ORIGIN_JSON. Origin is the exact closed CarrierAddress shape with explicit nullable line2/postalCode and country NG. No production shipper, account identifier, fee, tax or service coverage is seeded. Payment TEST corresponds to carrier SANDBOX; production requires LIVE and genuine qualified inputs. Neither owner forwards browser identity tokens or provider credentials across the boundary.

Source stale version is412; changes during HTTP are a safe repricing conflict. Current authority/object denial is401/403/404; malformed input400; invalid provider/rate/packing422; mode mismatch409; outage503. Keep the same key only for the same intended command; do not modify an old command body. A valid previously bound quote can proceed through checkout within its approval and expiry rules when a fresh rate is unavailable. UNKNOWN booking is a separate durable workflow and never implies stock dispatch.

Run the reviewed private/public OpenAPI checks and ENV=test Java25 python3 scripts/carrier/verify.py using the local Docker environment in the implementation report. The harness uses isolated owned PostgreSQL, actual HTTP, stateful synthetic provider/JWKS/KMS fixtures and checks original Docker states/volumes are preserved. Genuine account, service-area, origin, label and release qualification remain NOT_RUN until supplied configuration is available. Booking, cancellation, private labels and tracking acceptance are recorded separately; successful quote checks do not complete the full carrier task.
