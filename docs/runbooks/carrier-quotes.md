# FedEx delivery quote operation

API-181 is the customer cart delivery quote command. It requires an encrypted BFF session, current CUSTOMER authority, owned cart/address, CSRF, a stable Idempotency-Key and the quoted cart If-Match version. The only body fields are addressId and optional serviceCode; customers cannot supply a fee, account, origin, package weight or transport URL.

Commerce captures current approved NG market, destination and server packing in a short owned transaction. It releases locks before requesting private API-182 with a scoped Keycloak workload JWT and a KMS-signed actor assertion bound to exact body, route and correlation. Integration uses its configured FedEx account and OAuth adapter; the rate read never books a shipment. The exact single ACCOUNT rate must match the selected approved service and NGN. Missing eligibility, unsupported route, wrong currency, ambiguous rate or provider outage cannot produce an invented fee or manual fallback.

The private response body remains the closed carrier quote DTO. X-Nigson-Carrier-Mode is mandatory trusted owner metadata from the actual adapter: MOCK, SANDBOX (TEST transport) or LIVE. Commerce matches its qualified mode before binding the fee. Private command acknowledgement hashes include mode and approval identity. A mock fee cannot be relabelled as sandbox/live by changing source configuration or replaying a previous command.

Commerce then rechecks cart version, current ownership/organization, market approval, address hash and server package hash before atomically persisting carrier_quote and audit. Expiry is no more than five minutes and is clipped to current payment/carrier approval expiries. The provider snapshot pins the server shipper for future order/booking context. Existing valid quotes retain their fixed fee; checkout independently revalidates binding and expiry. Quote creation reserves no stock and does not initialize a payment. Matching successful source keys return the original acknowledgement without another HTTP/KMS call; current customer authority still applies.

Both boundaries are disabled by default. Integration requires NIGSON_CARRIER_ENABLED=true, NIGSON_SECURITY_ENABLED=true, FEDEX_MODE/BASE_URL/CLIENT_ID/CLIENT_SECRET/ACCOUNT_NUMBER and explicit NIGSON_CARRIER_SERVICES, NIGSON_CARRIER_DEFAULT_SERVICE, NIGSON_CARRIER_PICKUP_TYPE, NIGSON_CARRIER_APPROVAL and NIGSON_CARRIER_APPROVAL_UNTIL. Supported pickup policy values are DROPOFF_AT_FEDEX_LOCATION, USE_SCHEDULED_PICKUP and CONTACT_FEDEX_TO_SCHEDULE; selecting a value is an account/origin configuration decision, not a default route promise.

Commerce requires NIGSON_CARRIER_QUOTES_ENABLED=true, private security/workload/KMS configuration, NIGSON_INTEGRATION_BASE_URL, existing qualified pricing/fulfillment provider settings and NIGSON_CARRIER_ORIGIN_JSON. Origin is the exact closed CarrierAddress shape with explicit nullable line2/postalCode and country NG. No production shipper, account identifier, fee, tax or service coverage is seeded. Payment TEST corresponds to carrier SANDBOX; production requires LIVE and genuine qualified inputs. Neither owner forwards browser identity tokens or provider credentials across the boundary.

Source stale version is412; changes during HTTP are a safe repricing conflict. Current authority/object denial is401/403/404; malformed input400; invalid provider/rate/packing422; mode mismatch409; outage503. Keep the same key only for the same intended command; do not modify an old command body. A valid previously bound quote can proceed through checkout within its approval and expiry rules when a fresh rate is unavailable. UNKNOWN booking is a separate durable workflow and never implies stock dispatch.

The FedEx HTTP port also accepts an asynchronous output.jobId acknowledgement. It validates the identifier and uses the configured account with POST /ship/v1/shipments/results to retrieve that existing job. This endpoint is read-only even though it shares the /ship/ prefix; it can renew an expired OAuth token once. Shipment creation and cancellation cannot repeat automatically on 401. Pending/missing results remain unavailable and do not submit another shipment. An invalid initial acknowledgement preserves uncertain outcome. Protocol checks alone do not qualify the separately tested durable booking/label workflow. Official wire reference: https://developer.fedex.com/api/en-us/catalog/ship/v1/docs.html.

API-119 GET /internal/v1/shipments/{id}/provider-context is now a BP1 private source endpoint. It requires exact nigson-integration/logistics.read Keycloak trust and no signed actor, browser cookie, query or request body. A bounded repeatable-read transaction validates a verified paid unheld NGN order, FEDEX intent, current qualified mode, original booking UUID and hash-bound frozen parcels. The response contains only shipment/order identity and frozen logistics values. Mutable address identifiers/version/organization are omitted under CF-ORDER-001. A missing historical providerSnapshot.shipper fails closed; recovery cannot invent a current origin. Reads do not create a booking, alter stock, mark dispatch or change payment state. API-120 also uses its required BP1 private scope; its source acknowledgement increment is qualified separately from the remaining integration workflow.

API-120 POST /internal/v1/shipments/{id}/provider-result requires nigson-integration/logistics.write with no signed actor/cookie/query. NIGSON_CARRIER_RESULTS_ENABLED defaults false; enabling requires private security, existing configured private FileStorage and current fulfillment qualification. Optional fields are omitted on wire, not null. BOOKED supplies READY, actual tracking reference, private PDF object key and checksum. Source verifies exact environment/shipment prefix, booking UUID in trusted object owner metadata, private encrypted object, size/mime/checksum/version/ETag through the real S3 SDK outside transactions. It then rechecks immutable intent and atomically commits metadata/status/history/audit/outbox and commandId acknowledgement. Same successful command replays without another HEAD; changed-body keys conflict. UNKNOWN cannot supply ready/label evidence. Provider transit never debits stock; delivery follows recorded physical handover and cannot regress. A real accepted booking can be acknowledged during refund processing while the existing dispatch guard still forbids handover. Monetary state is untouched. Metadata failures return FULFILLMENT_RULE_VIOLATION; provider outages retain their own safe codes. Private labels remain current-OPERATIONS downloads with sixty-second presigned attachment URLs. Source metadata qualification is separate from integration execution/label/tracking acceptance and genuine provider/print/release qualification.

API-051 GET /api/v1/orders/{id}/tracking is a BP1 authenticated customer read. Current retail ownership or active organization membership is required; historical access does not require a new buying entitlement. It reads only commerce's repeatable-read projections, with no provider HTTP. Response includes safe ShipmentDTOs and latest100 status events in stable newest-first order; complete history remains durable. Raw provider/internal notes are withheld (note null), and private label keys/snapshots are excluded. More than100 shipments produces an explicit fulfillment error instead of an incomplete shipment list. Empty pre-shipment orders return empty arrays; source stock/payment data is not mutated. Current party suspension or membership revocation denies later reads.

The private creation context now rejects READY/SHIPPED/DELIVERED/CANCELLED with409; only outstanding CREATED/EXCEPTION intents can receive creation input. Existing integration provider IDs and persisted ACK bodies drive tracking/ACK recovery. This guard helps prevent a duplicate/restored creation job from starting another booking after source acknowledgement. Database restore can erase intent evidence: pause creation, reclassify affected nonterminal intents UNKNOWN and reconcile by original business reference. An absent provider reference never authorizes recreate. Infrastructure/restore and full integration workflow qualification remain required BP1 gates.

The initial request_hash is the canonical closed event payload hash, containing no address/account data; the future execution must bind its actual provider request before any side effect. FedEx Ship request construction uses the same frozen package weights/dimensions as rates, one canonical booking reference on every package, explicit ship date, approved service/pickup and total physical package count. Carton dimensions round upward to integer CM; the provider-required total weight rounds upward to one decimal while each carton weight remains exact. Up to40 packages request SYNCHRONOUS_ONLY;41–100 request ALLOW_ASYNCHRONOUS and later retrieve the accepted job instead of another create. PDF LABEL bytes are requested; label-stock and SENDER billing require explicit configuration, with no default genuine approval. Unsupported recipient/third-party billing or thermal stock fails closed in this reviewed subset. The pure builder does not call the provider, write a job or report BOOKED. Before invoking it, the execution owner must persist/fence its intent and bind the exact request plus provider/account identity. Durable worker/private label acceptance is recorded separately below.

Durable execution is separately enabled by `NIGSON_CARRIER_WORKER_ENABLED=true`; it requires security, carrier, intake and label flags. `NIGSON_CARRIER_WORKER_DELAY_MS` defaults to30000 and accepts1000–300000; one booking is processed per tick. Configure `NIGSON_CARRIER_CREATION_GENERATION` as a nonnil UUID retained outside database restore scope, and `NIGSON_CARRIER_CREATION_NOT_BEFORE` as an explicit UTC instant. No value is guessed at startup. Only original source events on or after that cutoff may create. The worker also requires the scoped integration workload identity, fixed commerce base URL, explicit approved label stock/SENDER billing and private storage settings. Defaults keep this composition disabled.

The worker commits paired120-second booking/job leases and request identity before FedEx HTTP. PREPARED/expired/legacy/account-mismatched records cannot submit another create. ASYNC resumes only the persisted provider job. LABEL_PENDING carries tracking proof; UPLOAD pins immutable PDF key/checksum/size before S3 HTTP; ACK persists the exact original source command before API-120. A lost upload response or process crash is reconciled through exact encrypted versioned-object HEAD. Lost ACK retries the same sorted scalar body, command UUID and timestamp without another context read, provider booking or upload. COMPLETE/SUCCEEDED means source accepted booking/private label, never stock dispatch. Active tracking retains the complete sorted physical-piece numbers in completed creation checkpoints. It leases only BOOKED records with a SUCCEEDED creation job and a due next_poll_at; creation state is never reset.
