# Commerce notification operations

API-122 supplies minimal current order/email context to exact integration notification.read workload JWTs. An inactive or unverified recipient fails closed. Integration validates the allowed job/type/order; this endpoint grants no consent and sends no message. Integration must call experience API-127 immediately before sending; unavailable eligibility suppresses/fails dispatch rather than allowing it. The residual withdrawal race after provider acceptance is recorded by the sender. No cross-owner SQL.

API-133 accepts exact notification.write workload JWTs and immutable SENT/FAILED/SUPPRESSED/UNKNOWN outcomes. Browser idempotency and durable job/state keys both deduplicate. Job UUID cannot be rebound to another order. Same-state contradictory reference409; late states are retained as history. SENT indicates provider acceptance, never order delivery. Owned audit and acknowledgement commit atomically. Failed work remains visible to OPERATIONS through API-163's integration-owned job view. Existing receipt ledgers retain minimal state/key/resource/hash; raw provider references and messages are not copied into audit. No purge job or retention approval is introduced; preserve business dedup when retention is eventually approved.

API-165 requires current ADMIN, no organization context, session CSRF and recent MFA15m. NIGSON_NOTIFICATION_TEMPLATES_ENABLED defaults false and fails before creating intent. Enable only with explicit NIGSON_INTEGRATION_BASE_URL under the same private target policy as job operations. Production has no mock fallback. Template syntax is literal text and exact double-braced flat allowlisted variables; nested expressions, helpers, triple braces and arbitrary schemas are rejected. EMAIL rendering escapes literal and variable HTML. BCP47/channel/classification and phase guards are enforced. A WhatsApp provider template identifier is metadata, not evidence of approval.

Template creation has no required If-Match in the master request and no read/version field. Forward any supplied quoted version exactly; the worker enforces stale versions and immutable activated revisions. New creates never synthesize version0. Actual worker ETag is forwarded when present; if a supplied version is used, a missing ETag is uncertain. Existing-version discovery needs an approved worker contract before an editing UI can infer versions.

Concurrent active lease returns409. A failed final audit leaves CALLING recoverable after lease expiry. Current ADMIN/MFA are checked on all cached replies. The HMAC covers the ephemeral destination and fully rendered request; only the keyed digest is persisted. Do not reuse phone consent HMAC/cipher keys.
