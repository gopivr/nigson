# Commerce catalogue

API-013–025/149 are implemented in the existing commerce transaction boundary. Public endpoints expose only published ACTIVE, non-deleted products with explicit eligibility in an enabled requested market. Missing/inactive markets and invisible product IDs return404. Public DTOs exclude status/version, wholesale prices, provider fields, object keys, checksums and shipping labels. Categories expose active directly linked eligible taxonomy; brands expose active non-deleted brands. Staff listing includes draft/archived and reviewed unpublished asset metadata under current CONTENT_EDITOR authority, with no-store responses.

All staff commands verify the exact current commerce editor/publisher role and issuer/subject mapping; ADMIN does not imply either content role. Organization contexts are denied. Cookie mutations require CSRF and durable Idempotency-Key. Root patch/publication/child creation take the Product If-Match version; SKU patch takes its own SKU version; taxonomy patch takes its taxonomy version. Create Product/brand/category has no existing version and starts version0. A matching replay checks current authority and returns the original response; changed canonical input409, stale version412. Unknown/repeated query, non-query body, duplicate headers/JSON and immutable/unrecognized mutation fields are denied.

Product creation is DRAFT/revision1. Root updates increment version/revision and atomically write redacted audit plus EVT-006. The envelope aggregate_version is the optimistic Product version; payload.revision is its public catalogue revision. Active request trace context is propagated when present. Validated specification values are mirrored in owned product_attribute records for the registered product_type filter. Only active owned taxonomy may be linked. Typed specifications and SKU units/scales use the latest active catalogue.metadata revision; missing/unapproved metadata fails closed. No real unit, division, product, price or eligibility is seeded. CarrierPackaging is required and staff-managed for SKU creation/patch, with exact quantity scale and representable full-package weight/dimensions. SKU code/unit/scale are immutable. Optional SKU weight cannot fall below the packaging unit weight. SKU creation increments the parent version/revision and audits the child without a direct event, as API-020 specifies; SKU patch also emits the parent EVT-006. Deactivation removes the SKU from public detail/new sale eligibility.

Publication requires CONTENT_PUBLISHER, expected root version, an active SKU/category, explicit enabled-market eligibility and a CLEAN/PUBLISHED public image. The files-owned local port validates immutable object keys and approved HTTPS delivery configuration, publishes clean public image/brochure references and increments asset versions inside the same commerce transaction. Shipping labels are always excluded, including staff catalogue DTOs. Root ACTIVE state, asset transitions, audit, event and command response commit together; audit failure rolls all of them back. ARCHIVE immediately hides the product from queries and conditional cache responses. Repeated current-state publication is a version-preserving no-op; archived products may be republished through the same prerequisites. Editing existing published roots follows the declared CONTENT_EDITOR API-018 command; no separate draft-revision table or extra approval workflow is invented.

Taxonomy mutations share a bounded global advisory transaction lock before Party/taxonomy locks. Reparenting validates ancestors and descendant height, rejecting self/ancestor cycles and depth above5, including simultaneous opposite reparenting. Referenced taxonomy is deactivated rather than deleted. Product commands take this lock, then `configuration:catalogue.metadata`, stabilize current actor authority with a Party share lock and lock the Product before SKU mutation. Configuration activation uses the same metadata lock, preventing a concurrent SKU/specification write from escaping compatibility validation. Files/market/inventory commands added in their tasks must also lock the Product when changing publication-relevant records. No provider HTTP occurs under these locks. Lock waits500ms/statements2s bound contention.

Catalogue search uses bound values, generated PostgreSQL simple search_vector and plainto_tsquery. Hyphens/slashes split lexical terms while the original query still drives normalized exact SKU ranking. Exact active SKU match ranks first, name-token match next, then ts_rank_cd and UUID. Category/brand/product_type/market filters precede ranking/pagination. Sort fields are a closed name/createdAt/relevance allowlist, with UUID ties. Input is200 characters/twenty lexical tokens, pages0-based/size1–100, statements1s. Timeout returns safe503 without query details. Public detail/summary availability is computed from active SKU/location balances (`on_hand-reserved-allocated>0`); it never authorizes stock reservations. Summary images and staff page categories/SKUs/reviewed assets resolve in bounded batches; staff assembly uses a constant number of queries instead of one set per product.

Read transactions use REPEATABLE_READ, so counts/pages/detail and nested owned references reflect one snapshot. Public ETags contain the maximum/current catalogue revision plus a digest of the exact representation, including current stock/taxonomy/assets. Conditional requests revalidate visibility and data before304; archived/ineligible objects return404 even with an old ETag. Public responses are public,max-age=0,must-revalidate and vary on Accept-Language; market is in the URL. Anonymous, staff and malformed/stale cookies receive the same public DTO; public reads do not access actor sessions or issue cookies. Browser bearer/signed private actor/token-query injection remains denied. No process data cache or cached authority/wholesale/stock decision is introduced.

The engineering anti-abuse read budget defaults1000 requests/second/replica, bounded1–10000 by NIGSON_CATALOGUE_READ_BUDGET_PER_SECOND. It stores only a counter/time window and fails429 beyond the bound; it is independent of authorization and production ingress/WAF release gates. Query lists fail closed beyond100 SKU/assets/product categories per representation or1000 unpaginated taxonomy entries, rather than silently truncating. NIGSON_PUBLIC_ASSET_BASE_URL must be an approved immutable HTTPS CDN base without credentials/query/fragment/traversal; local/test may use an explicit synthetic .test host. Production rejects local/reserved example/IP targets. Missing CDN configuration prevents publication/URL delivery, without any mock fallback.
