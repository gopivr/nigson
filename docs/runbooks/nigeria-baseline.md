# Approved Nigeria baseline

NGN-001 applies additive BP1 changeset commerce-20261010-ngn-001 after the unchanged domain/constraints/file-transfer migrations. Approved ADR-008 facts are NG/Nigeria, Nigerian Naira NGN with minor_unit2, and destination NG. Deterministic UUIDv5 metadata IDs are technical row identities, not provider accounts or route approvals. Currency is supported/active; market selling and destination delivery remain disabled. Tax/address rules are empty unresolved objects, returns/book null. Empty tax is never an approved zero policy, and no carrier origin or serviceable area is supplied.

On upgrade, compatible existing NG/NGN/destination IDs and commercial policy are preserved. A previously inactive supported NGN row is activated by the existing explicit currency approval, retains its ID/minor unit and increments version once; repeat migration performs no second update. Existing enabled market/destination policy is untouched. Conflicting NGN scale or NG currency raises a safe migration conflict before any metadata write. This does not qualify an existing market for release. Forward correction is required for a real conflicting database; never silently reinterpret past order money.

Rollback removes only this changeset's untouched marker-owned metadata. Modified or referenced metadata refuses rollback atomically; use approved forward correction. Preexisting rows remain, including already-approved currency support; rollback does not revoke the user's currency approval or overwrite earlier policy. Applied DATA-001/file-transfer SQL and logical change IDs retain their checksums. The seed introduces no table/FK/shared entity/cross-owner access and no provider HTTP.

PaystackAdapter sends NGN decimal1234.56 as integer123456 kobo, rejects third decimals/nonpositive/exponents/overflow, and rejects wrong currency/amount/domain on verify. NGN-001 qualifies this transport with a stateful local HTTP server/dummy credential; it creates no paid order or real financial settlement. Merchant/account verification and durable initialize/settlement/refund callback composition remain PAYSTACK-001/COM-PAYME-001 before BP1. Real provider credentials/routes/policies are separate NOT_RUN.

Run `make nigeria-check ENV=test` for fresh/repeated owner migrations, native baseline/market checks and actual HTTP minor-unit verification. Run `ENV=test python3 scripts/nigeria/migration.py` with pinned JAVA_HOME/local Docker for previous-BP1 upgrade/unchanged checksum/policy-preservation, pristine actual Liquibase rollback/reapply and populated/conflicting-data refusal. Both scripts isolate local containers and preserve original state. `PROFILE=ai ENV=test python3 scripts/local/cold_start.py` verifies two complete isolated setup rounds after new BP1 data migration; test containers stop and named volumes remain. Full build/contract/locked dependency and artifact checks remain required before acceptance.
