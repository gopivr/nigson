# Pricing books and immutable checkout quotes

API-027 is current SALES draft creation; API-150 is the bounded private SALES page. API-151 takes the latest parent's If-Match and creates a new draft ID/revision. API-028 requires current FINANCE, CSRF and MFA within15 minutes. Activation writes immutable entries, one pricing.changed.v1/audit and the durable response atomically. Current role/issuer/subject precedes replay. ADMIN does not imply SALES/FINANCE.

Currency must already be active and approved. NGN has scale2; even a third zero decimal in a supplied amount is rejected. Each book has at most100 entries under the common API array cap. Numeric duplicate quantity thresholds are ambiguous and rejected. Current SKU quantity scale and pack multiples apply. Greatest qualifying threshold determines the tier. Published records are not shortened or edited. A next revision of an active book requires its original finite interval to end before the next starts; an open-ended book requires a separately created code and an explicit API-162 market selection. Active intervals in one family cannot overlap. Different books cannot become competing defaults: each market has one explicitly selected book ID. Activation never enables a market or supplies actual prices.

API-026 is a bounded no-store authoritative retail read for NG/NGN2, current eligible active SKU/product, explicit tax/returns policy and active effective selected book. An organization requires current active membership and the exact configured buying entitlement, at BP3 or later; a missing/ineligible wholesale assignment never falls back. API-067 is current SALES/CSRF/idempotency/If-Match and atomically assigns an active effective DISTRIBUTOR book plus up to100 closed organization-market minimum rules; it audits and emits EVT-007 without changing organization or entitlement state. Organization-specific values override market defaults field by field; SKU-specific values override generic rules within each scope; SKU pack and the chosen rule pack combine by exact least common multiple. Order minimums remain a separate checkout subtotal check. Query/body/decimal/UUID/sort fields are closed. Browser bearer remains forbidden by the BFF security contract.

API-036 creates an immutable quote without reserving stock or invoking HTTP. Its transaction locks the current cart and current product/SKU, checks owned address/market policies, provider approval context, and the unexpired QUOTED carrier record's cart/version/market/address/packages/service/currency/mode. Canonical carrier address and package values bind the carrier hash. Packages use actual units/weight/tare and full/remainder cartons, at most100; missing/oversized/nonrepresentable rules fail closed. Weight must fit the declared three-decimal contract exactly; no guessed weight or rounding policy. A carrier address requires NG, E164 phone and the contract's region string. Rate lookup belongs before this operation.

The snapshot freezes cart/market versions, owner/organization, address, tax schema/approval, returns revision, book/tier/wholesale assignment and rule revisions, approved offer revision where present, carrier version/service/mode/package binding, all line totals, delivery, promotion revisions and provider approval context. Canonical SHA256 binds the entire commercial snapshot. Snapshot/response/stored expiry share canonical PostgreSQL microsecond precision (truncate after all caps, never extend validity). TTL defaults to300 seconds and accepts1..300; expiry is capped by book, offered revision, carrier, provider and adjustment validity. Exact HALF_UP line/tax rounding and minor-unit largest remainder discount allocation conserve totals. Delivery tax follows only the explicit approved launch tax schema treatment.

The nonexpired approved current OFFERED quotation revision supplies frozen agreed prices/discounts/taxes before ordinary wholesale/retail resolution. Exact owner/organization/market/quantities and approved total must match; rejected, expired, superseded or already accepted offers cannot open a new checkout quote. Current product/market eligibility and authority still apply. COM-QUOTE-001 owns offer commands and acceptance/order composition. Cart/fedex APIs are later tasks; synthetic database fixtures used here do not qualify those APIs or real provider routes.

Same-key replay returns the original quote and expiry. It does not reprice or create another snapshot. Both current cart organization and original snapshot organization are reauthorized before returning a cached quote; suspended entitlement denies replay. An expired quote requires a new request key for a fresh quote, and subsequent checkout must revalidate authoritative revisions/expiry before reservation. Busy concurrent keys return the existing documented409 and safely replay later with the same key. Audit failure rolls back all price/quote/event effects. Lock/statement waits are bounded. No stock effect occurs here.

The master/API-117 do not define its literal storage key; no arbitrary active entitlement grants buying. BP3 test fixtures explicitly use a synthetic key.

These are trusted reviewed deployment references, never browser data or provider qualification results. MOCK is local/test only; production requires LIVE. Payment TEST maps to carrier SANDBOX; other modes match exactly. Production cannot fall back to mocks. Owning payment/carrier implementations and release qualification must establish the actual references/account/currency/routes before enabling. No live account or qualification is supplied by this task.

BP1 rejects coupon requests. At BP2, an explicitly supplied coupon is revalidated against its active immutable rule revision, market, eligibility and remaining global/per-party budget. Its quote freezes the discount and rule revision; order creation reserves the coupon in the same Commerce transaction as inventory/order state. Verified payment settlement consumes the reservation; explicit cancellation releases it. Uncertain payment outcomes retain the reservation until reconciliation. Campaign-generated coupons inherit the approved campaign and remain party-bound with a single use. Promotions are never silently selected or applied without an approved explicit rule.
