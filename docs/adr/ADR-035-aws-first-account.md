# ADR-035: Terraform first-account bootstrap

Status: User-directed implementation, 24 November 2026.

No AWS resource IDs, state bucket, network, certificates, WAF or repositories are pre-created in the console. A small local-state bootstrap root creates an encrypted/versioned/private state bucket and an environment DNS zone. The first-account root uses that remote bucket and composes existing owner modules with defaults for a new account. Stage delegates stage.nigson.com using Squarespace NS records; production uses nigson.com and requires the registrar nameserver change. Terraform cannot prove domain control without that registrar action. Credentials use the AWS SDK chain, never Terraform variables or repository .env.

The first apply creates infrastructure without task definitions or services that require unpublished images. Existing compute and identity modules gain an opt-in infrastructure-only path; their default behavior and existing deployed resource addresses are retained through explicit moved blocks where necessary. Application activation requires real immutable image digests and configured application secrets, owner database bootstrap/migrations and identity realm provisioning. It does not invent provider account credentials, approved business policies or successful health. No arbitrary image is used as a placeholder. Internal services and databases remain private; public internal paths remain denied. Secret metadata may be created but secret values remain outside Terraform state.

Infrastructure defaults are documented starter settings, visible in a reviewed plan; they do not establish release/provider qualification. State/DNS are protected against accidental destruction. Existing environment roots remain supported; use only one root to own a given environment, never apply the first-account root over an existing deployment without state migration review. Mock-provider Terraform tests and validation are offline evidence only. Actual AWS resources are not created by this implementation session.
