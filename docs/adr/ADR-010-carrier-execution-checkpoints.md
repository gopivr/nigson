# ADR-010: Carrier execution checkpoints and restore generation

Status: Accepted technical implementation decision; genuine provider/release activation remains pending.

The integration-owned LOGISTICS_CREATE job uses its existing opaque cursor JSON as a versioned carrier checkpoint. It contains a stage, original source-event timestamp, original correlation, externally configured creation generation, account fingerprint and minimal request/outcome metadata. It never contains addresses, credentials or label bytes. Booking and job rows are locked in booking-then-job order, leased together for120 seconds and fenced by both row versions. Payment reconciliation retains its existing worker, cursor format and thirty-second lease. Carrier execution is excluded from that generic worker.

Only a first-attempt INTENT in the current generation with matching untouched intake hash may prepare a provider create. Its original source-event timestamp must be at or after the externally configured NIGSON_CARRIER_CREATION_NOT_BEFORE instant and no more than five seconds in the future. Preparation commits its actual request/account/mode hash before HTTP. Expired claims, prepared requests, legacy checkpoints, changed generations and uncertain outcomes never regain create permission. Accepted async job identifiers are persisted before subsequent read-only result retrieval. A missing reference is not proof permitting recreation.

NIGSON_CARRIER_CREATION_GENERATION is a required nonnil UUID when intake is enabled. Operations preserves it outside database restore scope, pauses creation during restore and changes it and advances the creation cutoff before resuming affected restored workloads. Replayed historical outbox events cannot acquire creation permission merely by receiving the new intake generation. Affected source orders also require review before any new fulfillment intent is issued. Old/legacy pending jobs require reference reconciliation; deployment must not mass-rewrite their generations or reset uncertainty. The application cannot infer erased evidence if both database and external generation are rolled back together; restore qualification remains a BP1 gate.

No owner, table, foreign key, public API or event shape changes. Existing schema cursor supports this kind-specific checkpoint; old carrier jobs remain durable but cannot create automatically. The new startup configuration intentionally fails closed. A worker's fenced stale outcome cannot overwrite a newer generation; provider reference reconciliation handles an accepted response lost before persistence. ADR-011 defines private label production and acknowledgement. Active polling, cancellation and staff reconciliation remain CARRIER-001 work.
