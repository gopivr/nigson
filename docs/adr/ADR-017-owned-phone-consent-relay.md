# ADR-017: Owned phone consent and fixed BFF relay

Status: Accepted technical design; MSG-001 implementation IN_PROGRESS.

Commerce retains browser session/CSRF/current party authority. Experience owns encrypted communication destinations, proof attempts, explicit channel-purpose grants and suppression. Existing public APIs183–186 stay unchanged. Add fixed private companions201–204 so commerce can delegate a fresh current CUSTOMER actor bound to exact method/path/body/correlation; no browser-selected route, phone recipient lookup or cross-owner SQL. Verify/withdraw versions are inside the signed private body. Private ingress/JWT/client/audience/operation/actor guards remain mandatory. Source rechecks current session/party before returning a relay result. No bearer token or cookie is forwarded to experience.

Proofs use CSPRNG six-digit codes,10-minute expiry, five committed failed attempts and three proof requests/hour/party+destination. Codes/addresses use experience-owned AES256-GCM with distinct record/type AAD and KMS purpose; lookup/proof HMAC keys are separate from encryption. Idempotency request hashes include keyed phone/code fingerprints, never plaintext phone or a brute-forceable bare code hash. Proof failures return safe errors after committing attempts. Confirmation grants only the requested channel/purposes; global phone/channel suppression dominates historical grants, including another party using that phone. No implicit re-opt-in clears suppression. A reviewed re-opt-in/key-migration policy is separate work, never guessed.

API187 uses stable job UUID nameUUIDFromBytes(ASCII contact-verification:<verification UUID>) and returns the original encrypted proof's minimal context only while pending/unexpired/unsuppressed. Worker dedup uses that same business key/UUID; replay cannot choose another job or issue a fresh proof. Expired code ciphertext is erased on access and by bounded cleanup. No phone/code in events, audit, logs or metrics. Public destination lists are masked and bounded. Existing owner tables/constraints and EVT028/023 are reused; no DDL or owner change. One active destination per party/channel is serialized by owner locks; different destinations require explicit withdrawal.

All phone features default disabled. Missing security/key policy fails enabled startup. Local dummy keys are allowed only in local/test; other environments require purpose-bound KMS unwrapping before DB work. Encryption-key renewal can retain old decrypt keys; lookup/proof HMAC identity must stay stable until a separately reviewed data migration. Genuine sender/template/account/retention and provider/restore qualification remain NOT_RUN. This decision does not approve auth/MFA SMS or newsletter/campaign activation.

Enabled experience requires an explicit approved policy-version allowlist (`NIGSON_PHONE_POLICY_VERSIONS`, at most10 versions). Arbitrary client policy identifiers cannot issue/activate proof. No default approval is invented. The public list is bounded at100 records per party; creation is serialized per party and rejects expansion beyond that existing closed response capacity. Records are preserved; this is not a retention/purge policy. API127 phone eligibility releases plaintext only for an active requested-purpose grant and no current suppression. API175 accepts exact integration consent.write only, atomically deduplicates immutable command UUIDs and persists global phone/channel suppression with audit; it cannot grant consent. EMAIL/newsletter eligibility remains its separate implementation and is not simulated by the phone feature.
