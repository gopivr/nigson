# ADR-016: Immutable trusted carrier account binding

Status: Accepted technical design; CF-CARRIER-007 implementation qualified offline (native282, independent financial66, full179 Java/334 gated,74 contracts). Accepted source 2cb1643de0a01f5f935f5a24e929b1073f5c22bf. Whole CARRIER-001 remains IN_PROGRESS.

CF-CARRIER-007: intake/execution bind the configured FedEx account, but earlier rate/order snapshots did not. A fee obtained using account A must not authorize checkout or a shipment using account B.

Commerce requires explicit nonsecret NIGSON_CARRIER_ACCOUNT_FINGERPRINT when carrier-dependent pricing or fulfillment is enabled. It is the exact existing adapter SHA256 identity over canonical provider FEDEX, transport mode (MOCK/TEST/LIVE) and account; no guessed account, credential, or production fallback. Credential rotation for the same account does not change the identity. Mode checks remain separate.

Private API-182 adds X-Nigson-Carrier-Account-SHA256, bound to the actual configured adapter and durable quote command hash. Rotation cannot replay an old quote under a new header. Commerce accepts only one valid header matching configured identity. Persist it in existing provider_snapshot JSON, then hash-bind it into commercial checkout and freeze it into order and shipment snapshots. Private API-119 gains required accountHash; integration compares it to its captured/current adapter identity before preparing any provider write. Public rate/checkout/order/shipment DTOs and EVT-027 stay unchanged.

Existing quote uniqueness does not include account. Never overwrite a row's account during refresh/upsert or reuse a stale-account acknowledgement. Missing legacy identity fails closed for new checkout/creation rather than backfilling from current configuration. Paid historical snapshots and UNKNOWN/submitted checkpoints are not rewritten, charged again or granted new creation permission. Original provider result/cancellation/tracking evidence remains reconcilable under existing identity, mode and physical guards.

No DDL or owner-boundary changes: existing owner-local JSON columns carry the metadata, no cross-owner SQL/FK/shared entities. Source uses only trusted private responses and explicit server configuration, never browser account fields. Additive private protocol rollout requires pausing new rate/checkout/creation traffic and deploying all owners with matching qualified fingerprint before resuming; old closed context readers reject the extended body. Do not reset generations/checkpoints to bypass rotation. Missing configuration fails startup when affected features are enabled; disabled features remain disabled. Genuine account/route/private deployment/restore qualification remains NOT_RUN until actual metadata is supplied. BP3 quote API-195 remains dependency-bound.
