# ADR-013: Scoped staff carrier reconciliation

Status: Accepted technical contract refinement; native150/no skips, full167 Java/303 gated,71 contracts and nine reproduced artifacts PASS; accepted source d82734d5ab1728cab93feb1143359d73c5f38bc6.

API-191 already requires commerce to request integration-owned reconciliation and return its real job identifier. API-140 lacks a shipment lookup; API-141 permits only retrying FAILED jobs and must not reset an UNKNOWN carrier side effect. Add private API-196 POST /internal/v1/carrier/shipments/{id}/reconciliation with exact nigson-commerce `carrier.reconcile_WITH_SIGNED_STAFF` workload scope, current originating OPERATIONS and recent MFA assertion bound to the method/path/body/correlation. Body is closed `{bookingRequestId,mode,reason}`; Idempotency-Key is the persisted source command UUID. Response matches API-191's closed `{shipmentId,state:BOOKED|UNKNOWN|FAILED,jobId}`. No owner-boundary or schema change.

Commerce API-191 requires the existing BFF session for trusted actor delegation, CSRF, If-Match and idempotency. It verifies the current staff and owned shipment/NGN market/frozen mode/reference, persists its original private request/command before unlocked KMS/token/HTTP, and records the true ACK or UNKNOWN. Replay retains original version/request/UUID even if a provider acknowledgement advanced shipment state. Cached responses still require current authority; changed-body keys conflict. Unknown remote diagnostics remain private.

Integration locks booking then its matching LOGISTICS_CREATE job. It verifies shipment, original booking UUID, owner/kind, mode/account and checkpoint identity. A live booking/job lease is left intact. Booked jobs remain SUCCEEDED; a nonterminal polling deadline may be advanced without resetting terminal tracking. Unleased pending/unknown/failed creation jobs enter UNKNOWN with unchanged cursor, request hash, attempts and provider identifiers; they may reconcile existing evidence but cannot become fresh creates. Missing rows never manufacture a job or booking; callers retry after real intake/recovery. Cancelled intents reject invalid transition. Duplicate commands return the saved acknowledgement with no second queue mutation.

No provider HTTP occurs in API-196. Worker processing and source API-120 maintain their existing guards. Staff reconciliation never dispatches stock, cancels a carrier booking or refunds money. Cancellation initiation is a separate required carrier workflow and cannot be hidden in free-text reasons. No table, FK, event or service-owner change; existing private scopes and public DTOs remain compatible. New scoped identity configuration must be deployed before activation; offline JWT/actor qualification precedes acceptance.
