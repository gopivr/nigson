# ADR-029: Automatic PandaGo booking after verified payment or COD confirmation

Status: User-directed implementation, 17 November 2026.

Commerce owns order/payment/inventory truth. With NIGSON_PANDAGO_BOOKING_ENABLED, a one-second intake poll creates a complete shipment intent and EVT-027 in one local transaction for each eligible order. Prepaid requires independently verified successful Paystack amount/currency/mode and allocated stock, not a browser redirect, payment flag or unverified webhook. Confirmed COD remains UNPAID, skips Paystack, allocates stock atomically and is immediately eligible. Current holds and cancellation exclude intake. Order-first locks and existing shipment claims exclude duplicates/manual splits. Malformed orders are isolated so they cannot block other eligible orders. Only orders created at/after NIGSON_CARRIER_CREATION_NOT_BEFORE are automatically admitted; this does not backfill historic paid orders.

Integration consumes EVT-027 in its inbox transaction, with stable booking_request_id as client_order_id. It owns provider HTTP and the existing carrier_booking table. The nullable 026 additive columns store reference, generation, source timestamp, prepared timestamp, account hash and minimal durable result only; never customer addresses/phone or credentials. Old rows without these fields cannot create automatically. API-119 reads frozen Commerce context with exact logistics.read workload credentials; API-120 receives durable no-label results with exact logistics.write credentials. No cross-owner SQL/FKs.

The carrier worker uses 120-second leases and row-version fencing. Quote/geocoding reads precede preparation. Re-quote must match the frozen checkout delivery fee; fee drift fails safely rather than changing a paid order. The collection amount is the frozen order grand total for COD; PAID requests also carry that frozen total. A transaction commits prepared_at/request hash/account before confirmation HTTP, and only its live claim in the current externally configured generation may perform that POST. A crash/timeout after preparation becomes UNKNOWN and never grants create permission again. Persist a successful provider order ID and result before acknowledging Commerce. Owner acknowledgement retries replay the identical result/command without another provider POST. If response loss leaves no provider order ID, keep UNKNOWN for operator/provider reference reconciliation; do not invent a search API or assume a missing local record proves non-creation. A known provider ID permits read-only provider order retrieval, never recreation.

PandaGo does not issue a PDF shipping label. BOOKED requires the real order ID and produces READY with provider_order_id exposed in authenticated tracking. Reject label evidence for PandaGo. Booking/COURIER_ACCEPTED_DELIVERY does not debit stock or gate internal preparation; physical handover remains the existing explicit stock-dispatch operation. Existing webhook/cancellation/staff reconciliation routes remain disabled until their independent workflows are configured. No internal preparation-time buffer and no synthetic schedule workaround. Genuine scheduled orders retain their chosen Unix timestamp and provider minimum 45-minute window; never silently change a stale schedule to immediate.

Restore controls from ADR-010 remain: generation and creation cutoff live outside DB restore scope; pause booking during restore, rotate generation and advance cutoff before resume. Do not rewrite old prepared checkpoints. Production defaults remain disabled. Local opt-in uses the existing user-approved Paystack TEST/PandaGo stage setup; no runtime mocks. Offline HTTP/PostgreSQL acceptance does not establish PandaGo quality-audit approval.
