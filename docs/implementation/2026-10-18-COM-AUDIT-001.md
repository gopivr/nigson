## Summary

Implemented API-134, `GET /api/v1/commerce/staff/audit-records`, as a read-only Commerce query over the existing `commerce.audit_record`. The endpoint uses the current BFF session and requires a currently active Commerce ADMIN assignment on every request. It supports bounded pages (maximum 100), validated resource/action/time filters, and allowlisted stable sorts. Query values are bound parameters; sort fragments come only from a closed switch. The count and page execute in a read-only repeatable-read transaction with a three-second timeout.

The existing AuditWriter, audit table, owner grants, append-only behavior, audit event vocabulary, and public API-134 DTO fields are preserved. Persisted JSON is redacted again before response serialization. The route is `no-store`, emits a bounded `nigson.audit.queries` metric only after successful reads, and maps database failures through existing safe error handling. Repeating a GET returns the same page and creates no audit, outbox, or idempotency state; API-134 defines no such side effect. No retention, IP access, export, or new access policy was introduced, and no database migration was needed.
