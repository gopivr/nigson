## Summary

Implemented API-110 as a sanitized Experience-owned engagement report over the existing lead, career application, review, newsletter subscription and campaign tables. Required `from` and `to` are parsed as instants and queried using UTC `[from,to)` boundaries with a maximum 366-day range. The query runs in a bounded repeatable-read transaction with a PostgreSQL statement timeout. It returns only state counts, active subscriptions created in the requested interval and campaign identifiers; applicant, contact, lead, review and campaign display content is excluded. Responses are `no-store`.

Access requires the exact `nigson-commerce` private workload route and `report.read_WITH_SIGNED_ANALYST` plus a signed current ANALYST actor. Organization-scoped actors are denied because API-110 has no organization selector. The report appends one minimal Experience audit record per successful request and increments a bounded owner/report metric after commit. No command side effects exist, so If-Match, idempotency and outbox behavior do not apply. The query touches no Commerce or other owner data.

The existing Experience schema stores campaign definitions but has no participation/entry table or event. The API preserves its `campaigns:[{id,entries}]` DTO and currently reports zero tracked entries for returned campaign definitions; that value does not represent Commerce wheel/reward participation or establish that no untracked real-world participation occurred. Adding participation capture requires an owned source contract and is outside this read-only API increment. No policy, retention rule or cross-owner shortcut was introduced.

API-110 has no monetary or refund fields. Refund totals remain the responsibility of Commerce API-075; no cross-owner refund query was added.
