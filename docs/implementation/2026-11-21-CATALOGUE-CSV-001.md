# CATALOGUE-CSV-001

Frontend import workflow implemented using the existing owner-authorized catalogue, SKU and commercial-price APIs. No new backend endpoint, migration, provider call or database mutation was performed during development. Existing unrelated category/affiliate changes retained. Changes are uncommitted; commit/acceptance hash NONE.

Admin > Products > Import CSV provides a downloadable CSV header template, column guidance, file selection, read-only preview and explicit save confirmation. Each row shows create-draft/update, SKU, name, category, prices/minima, all provided fields on expansion and individual error/status. CSV only (not native XLSX); 2 MB, 1–50 rows, one product/one SKU per row. Parses BOM, CRLF, quoted commas/newlines and escaped quotes, rejects duplicate/unknown headings, malformed records and duplicate SKUs. No spreadsheet formulas are evaluated.

Columns: sku, name, slug, category, description, retail_price, wholesale_price, wholesale_minimum, distributor_price, distributor_minimum, unit, quantity_scale, pack_size, division_code; six measured packaging fields; optional supported descriptive specifications and specifications_json. Brand is not a sheet column. Resolve exactly one existing active Nigson brand; missing/ambiguous configuration blocks the preview. Existing non-Nigson products, ambiguous SKUs, multi-SKU products and archived products require manual review. Category name or slug must resolve to one existing active staff category, including empty categories.

New products require name/description/category/retail price and all measured packaging fields. SKU identity matches existing products case-insensitively; blank updates preserve existing fields and unprovided prices/specifications. Existing unit/quantity scale/pack size are immutable. Optional features/highlights/packaging/carton_specs use pipe-separated lists; custom JSON supports bounded strings, booleans and text arrays. Images, stock, status/publication and partner approvals are excluded. New products remain drafts under the existing create API. Pack size defaults to 1, unit to unit and quantity scale to 0; no shipping weights/dimensions or selling prices are fabricated.

Pricing uses ProductPricesService, including optimistic commercial-price state and existing authorization. No metadata price fields are written. CSV prices are naira decimal strings. Business amount/minimum pairs are required together, with positive scale-compatible pack multiples. Blank business prices preserve existing values. Existing shared retail book remains capped at 100 entries; RetailPricingService preflight rejects capacity overflow before product writes. This increment does not increase that backend limit or claim unlimited catalogue pricing capacity.

Save runs sequentially and stops on the first failure. Product, SKU, packaging and price operations retain existing separate transaction boundaries. A successful earlier step is not rolled back; the row shows which stage failed and warns to review the product before re-upload. New draft ID is retained after a SKU failure. A reviewed batch can only be submitted once in the page; another upload performs fresh validation. Native reload protection and route deactivation guards prevent accidental navigation during saving. No automatic retries of uncertain outcomes. Existing server uniqueness, versions, idempotency and permission rules remain authoritative.
