## Summary

Validated Commerce fulfillment ownership and conservation behavior for API-051, API-119, API-120 and API-160. Existing API-051/119/120 state machines remain authoritative: customer tracking is an owned, bounded, no-store read; API-119 exposes only the frozen paid shipment intent through exact `nigson-integration/logistics.read`; API-120 accepts exact `nigson-integration/logistics.write`, durably deduplicates the source command, verifies private labels outside SQL transactions, and commits accepted state/history/audit/EVT-009 atomically. UNKNOWN and failed booking outcomes do not become READY, dispatch stock, or grant a fresh create attempt. Existing HTTP acceptance covers retries, lost acknowledgments, stale/out-of-order results and prevents DB locks across provider/storage HTTP.

Added the missing API-160 route and generated operation. It is permanently disabled for launch FedEx until a provider callback signature contract is approved. It returns `FEATURE_DISABLED` without parsing or storing the body or changing shipment events, inventory movements, or outbox state. FedEx polling remains authoritative. No signature format, route qualification or callback behavior was invented.

Added PostgreSQL coverage proving that a longer matching postal prefix wins before rule priority, and that an ambiguous equal-specificity rule is rejected. Existing shipment/stock tests verify claimed quantities, paid/unheld dispatch, exactly-once stock debit, verified physical receipt before return, cumulative return caps, idempotent replay and concurrent dispatch/claim races.

Public DTOs, schema ownership, shipment/event schemas and migrations are unchanged. API-051 continues to return `Cache-Control: no-store` (`TEST-CACHE-OFF`). No cross-owner SQL or provider HTTP was added to Commerce transactions.
