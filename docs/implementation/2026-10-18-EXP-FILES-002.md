# EXP-FILES-002 implementation report

Specification: 1.1.0 / architecture 1.0 with ADR-008  
Task status: DONE (offline engineering; live career intake remains configuration-gated)  
Phase: EP07 / BP2 offline implementation

Implemented API-157, `POST /api/v1/career-upload-sessions`, over Experience-owned `experience.upload_session`. The anonymous endpoint requires a valid local/provider anti-spam proof and an idempotency key, rejects unknown request fields and query parameters, and issues only the `CAREER_CV` purpose. Sessions have a 30-minute expiry and a 5 MiB limit; distributor proof uploads cannot be selected. The bearer token is 256 bits of random entropy, its SHA-256 hash is stored in the session table, and the replay response stores the token only in AES-GCM encrypted form. Repeating the same request key returns the same public capability without consuming anti-spam proof twice; reusing the key for a different request conflicts. Audit and session/idempotency writes share one Experience transaction.

Career intake settings remain fail-closed unless privacy policy, retention, recipient group, encryption keys and anti-spam configuration are complete. Production continues to require KMS-backed keys and a real approved anti-spam adapter. This increment issues upload sessions only; it does not claim binary transfer, scanning or clean download qualification, which use the existing file APIs/workers. No live object-store credentials or provider calls were used, and no cross-owner SQL or schema migration was added.

Acceptance evidence: the isolated PostgreSQL/LocalStack harness ran 13 Career tests with zero failures, errors or skips. This includes the actual anonymous Spring HTTP route, response shape/cache policy, invalid anti-spam rejection without writes, idempotent replay, token-hash/purpose/owner/expiry/size persistence, encrypted replay storage, unknown fields and missing idempotency rejection, plus career persistence and token-encryption unit coverage.
