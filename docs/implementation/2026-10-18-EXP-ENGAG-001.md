# EXP-ENGAG-001 implementation report

Specification: 1.1.0 / architecture 1.0 with ADR-008  
Task status: DONE (offline engineering; live campaign activation remains gated)  
Phase: EP07 / BP2 offline implementation

Implemented Experience engagement APIs API-096/097/098/108/109/176 against the existing Experience-owned review and campaign tables. Product reviews require a verified Commerce API-121 purchase proof for the exact customer, order line and product before Experience writes anything. Reviews begin in PENDING, public reads include only PUBLISHED records and return no customer or order identifiers, and the signed moderation endpoint enforces role/scope, If-Match versioning, idempotency, audit and EVT-021 publication in the same Experience transaction. Testimonials cannot carry purchase identifiers. Campaign writes enforce an allowlisted display-only configuration and Commerce-resolved market; public campaign reads expose published, active records only. Commercial rule IDs are rejected because no private Commerce eligibility API is defined here; campaigns do not mutate discounts or entitlements.

No cross-owner SQL or schema migration was added. Remote Commerce market and purchase-proof HTTP calls happen before local database transactions. The purchase proof adapter is fail-closed, bounded, redirect-disabled, HTTPS-only outside local/test, and enabled only with explicit private client configuration. A stateful in-process Commerce mock covers market resolution and eligible/ineligible purchase proofs. Signed workload routes and actor scopes are registered for moderation, campaign writes and private review queue reads.

Public review DTOs expose the generic display name `Nigson customer`; this avoids introducing unapproved identity/alias disclosure. No review alias consent field is defined by the current DTO contract. Campaign creation is available offline but should remain disabled for live use until approved commercial rules and configuration are supplied.
