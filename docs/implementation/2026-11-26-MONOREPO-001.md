# MONOREPO-001 — repository consolidation

Date: 2026-11-26. Scope: local repository migration; no AWS deployment or remote push.

## Result

Canonical remote: `https://github.com/gopivr/nigson.git`.
Backend modules, Terraform, state configuration and scripts retain their Git-relative
paths. UI files live under `frontend/`, preserving the npm lockfile and Angular
federation layout. Workflows live in root `.github/workflows/`.
The UI build and infrastructure deployment use the same Git revision and the
built-in read-only repository token. No cross-repository PAT is required.

The migration branch is `codex/unify-monorepo`. The migration merge has the
original backend and original UI commits as parents, preserving both histories:

- Backend: `9f3f2fef8dec274326fb571de65f78dba6543d21`.
- UI: `48722b6e45e302da77cd38424f52f5c3d5908a98`.

Root Make targets `ui-install`, `ui-test`, `ui-build`, `ui-dev` run inside frontend.
Use Node 24.15.0. The UI production build requires the real public reCAPTCHA key
and an output directory which does not already exist.

## Recovery and local files

Before moving files, both repositories were clean. Full `--all` Git bundles,
a manifest and the original UI Git directory were saved under the private,
ignored `.monorepo-backups/20261126/` directory. Never upload this directory.
To recover an original checkout independently, use `git clone --branch main`
with the appropriate local bundle path and a separate destination directory.
The preserved bundle main refs point to the original pre-migration commits.
Local dependencies, build caches and runtime files were retained on disk.

The original backend tracked `.env`, `.local/` provider files and cookie jars.
These are removed from the new index and ignored, without deleting local files
or rewriting history. Previously committed credentials remain in history and
require rotation by their account owners. Generated Python bytecode is likewise
excluded from the new frontend tree.

## Handoff

1. Review the local migration branch and its merge parents; push the branch to
   `gopivr/nigson` and merge through the normal review process.
2. In that repository, retain AWS secrets and the `stage` environment. Set
   repository variables `AWS_REGION=us-east-2` and the real public
   `NIGSON_GOOGLE_RECAPTCHA_SITE_KEY`. Review existing stage protections.
3. Use the root UI workflow for subsequent staging releases; see
   `frontend/deployment/AWS.md`. No infrastructure read token is needed.
4. Disable the old UI repository's deployment workflow before resuming releases
   from the monorepo, to prevent two repositories deploying concurrently. The
   old remote repository was not modified or archived during this task.
5. Clone the canonical repository for future work. Teammates with separate old
   clones should migrate any unpushed work explicitly before retiring them.

Terraform account, region, state keys, buckets and resource addresses are
unchanged. No cloud apply, GitHub secret changes, repository setting changes,
provider calls or production activation were performed.
