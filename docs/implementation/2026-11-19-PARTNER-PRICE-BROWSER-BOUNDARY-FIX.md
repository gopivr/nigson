# Session report: PARTNER-PRICE-BROWSER-BOUNDARY-FIX

Date: 2026-11-19, Asia/Calcutta. Specification 1.1.0 / ADR-030. EP08/BP3. Status IN_PROGRESS for runtime/browser acceptance and acceptance commit; implementation and targeted offline checks passed.

User reported approved-account catalogue cards still showing retail prices and cart PUT returning CART_RULE_VIOLATION. Root cause confirmed in TrustFilter: public GET price requests without explicit organizationId skipped the BFF cookie entirely, so PriceQueryService received a null actor and selected retail. Protected cart writes received the actor and selected the business context. Prior direct domain tests did not exercise this filter boundary; PublicRetailPriceTest explicitly preserved the obsolete behavior of ignoring all price cookies. Product cards additionally discarded the minimum/pack from their own current price response, allowing stale input minimums to reach the quantity stepper. A generic 422 alone does not identify every live SKU rule; missing business prices still intentionally fail closed.

TrustFilter now optionally authenticates public price reads: no cookie means guest retail; a valid cookie resolves current Commerce identity; supplied malformed/expired cookies fail AUTH_REQUIRED rather than silently downgrade to retail. Other public catalogue routes retain their prior cookie behavior. GET does not require mutation CSRF; existing CSRF/private-workload/credential-header protections remain. Responses already use no-store.

ProductCardComponent now waits for the current price response, stores its minimum/pack, displays the minimum and passes those values to productForStepper. Cached input retail values are not used as a display fallback after a failed current account price read. Add to Cart consequently starts with the currently applicable business minimum pack.
