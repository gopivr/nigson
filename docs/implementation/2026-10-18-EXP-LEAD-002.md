## Summary

Implemented Experience quote-request API-088 on top of the existing Experience-owned lead and quote-association model. Input parsing is closed and bounded, quantity precision is checked against Commerce’s current product scale, customer actor proof and exact signed scope are required, and idempotent replay returns the original response without another Commerce lookup. New leads, requested SKU rows, EVT-016, audit and the response record are persisted through the Experience owner transaction. The event contains no contact or message PII. Missing recipient-group configuration disables intake; no recipient, sender, price or commercial rule was inferred.

Commerce exposes private read API-206 for exact requested SKU/market/party/organization eligibility. It validates the current NG/NGN market, active party mapping, published SKU and market eligibility, and current organization membership/entitlement when requested. Experience calls it outside its transaction using the exact `catalogue.quote-eligibility.read` workload scope and bounded HTTP response validation. Production URL configuration requires HTTPS. A stateful local test mock is explicit and test-only; live Commerce qualification was not performed.

API-130 and API-131 are generated under the Experience OpenAPI contract and enforce exact Commerce workload routes. Context reads are QUOTE-only. Quote association is immutable, command-ID idempotent, and acknowledged only after owner persistence. Public request/response DTOs are closed and no Commerce-owned SQL was added to Experience.
