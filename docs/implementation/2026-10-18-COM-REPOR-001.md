## Summary

Implemented API-075 as a sanitized Commerce-owned report over existing orders, successful refunds, order lines, SKUs, currency and inventory tables. The request uses UTC instants with an inclusive `from` and exclusive `to`, requires a positive range no longer than 366 days, accepts one currency and an optional active organization, rejects unknown/repeated parameters and request bodies, and bounds product and stock results at 100 rows (overflow fails explicitly). Queries apply a 2.5 second PostgreSQL statement timeout inside a three-second repeatable-read snapshot. Totals subtract successful refunds; amounts use the currency's configured minor unit. Responses are `no-store`.

Authorization requires the current `ANALYST` role in the same report snapshot. Organization-scoped actors can read only their own organization; explicitly requested organizations must exist and be active. Successful reads append a minimal redacted Commerce audit record and increment the report metric after commit. No cross-owner SQL, new migration/table/event/outbox, retention policy, or access policy was added. Existing report DTO fields were preserved.
