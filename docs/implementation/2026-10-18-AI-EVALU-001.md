## Summary

Implemented AI-owned API-180 immutable evaluation suite revisions, API-147 policy-linked evaluation results and sanitized insight drafts, and the AI report contract at `/api/v1/staff/reports/ai`. Suites contain 200–500 validated synthetic/sanitized cases and immutable scoring thresholds. Email/phone-like direct identifiers are rejected. Suite creation uses durable idempotency and an append-only AI audit record. Evaluation runs require the private `nigson-commerce` workload scope plus an ES256 `X-Nigson-Actor` assertion pinned to configured public keys; the proof binds exact method, path, raw body hash, correlation ID, actor identity, ADMIN role, operation scope and recent MFA. The owner and `If-Match` suite revision are checked before execution. Idempotency races serialize on a stable key and return the original result; a changed request hash conflicts.

Evaluation is deterministic and uses only the stateful local mock, bounded to 500 cases with a fixed internal time budget. Results record policy, groundedness, leak, injection and latency gates. Failed policy or grounding gates produce a sanitized draft, never activate a policy, and always report `activationEligible=false`. A local evaluator failure rolls back result, audit and idempotency writes, allowing a safe retry because no external side effect occurred. No event is specified for these operations, so no outbox event was invented. Existing AI owner migrations already supplied append-only suite/result tables, audit and idempotency storage; no DDL change was necessary.

API-148 is an owner-local UTC-bounded query over `ai.ai_run`, restricted to at most 90 days and the exact ANALYST role. The current AI schema does not persist intent or empty-search dimensions, so `topIntents` is empty and `emptySearches` is zero rather than inferring labels from prompts or private results. This limitation is documented in `docs/runbooks/ai-evaluation.md`; instrumentation/schema expansion should be handled by the relevant future AI contract task.
