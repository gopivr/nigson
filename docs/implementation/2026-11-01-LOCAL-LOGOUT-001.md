# Session report: LOCAL-LOGOUT-001

Date: 1 November 2026 (America/New_York)
Specification/architecture: 1.1.0 / 1.0 plus ADR-008
Task status: DONE locally
Phase: local identity/session testing

Problem: authenticated `POST /bff/logout` fell through the Spring Security route list to `anyRequest().denyAll()`, returning 403 before the session controller ran. The frontend suppresses logout HTTP errors, so its local signed-out display concealed the still-active server session. Reproduced through `localhost:4200` with a separate `retailB` Keycloak fixture login; login succeeded and logout returned 403. No user's browser session was read or reused.

Change: allow only authenticated POST requests on the exact `/bff/logout` path. Existing TrustFilter cookie/CSRF validation, current authority checks, controller input validation, atomic session deletion/audit and provider revocation remain in force. GET/other unlisted routes remain denied. Updated actual HTTP regression coverage for anonymous/missing/wrong CSRF requests and corrected the extra-body-field assertion to expect the controller's 400 validation error now that it is reachable; previously the route policy's 403 prevented that validation.
