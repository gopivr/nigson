# INT-NOTIF-001 — Integration notification templates

**Status:** DONE for dependency-ready offline engineering. **Date:** 2026-10-20.

API-142 now accepts private, signed-admin notification template registration at `POST /internal/v1/templates`. It validates a closed template DTO, permits data-only `{{name}}` substitutions, rejects executable/malformed placeholders, and renders substitutions with HTML escaping when applicable. Template code/locale/channel revisions are immutable and monotonic. The endpoint requires a stable idempotency key, supports optimistic `If-Match`, commits the template revision and redacted audit atomically in the Integration owner, and returns the preserved `{id,code,revision,active}` response with ETag and `no-store`. Exact workload client, actor scope, ADMIN role, unbound organization and recent MFA are enforced before writes.

No migration was needed. The implementation uses the existing Integration `notification_template`, local idempotency response and append-only `audit_record`; API-142 has no domain event or external side effect, so no outbox was added. Existing `notification_job`, `notification_dispatch` and unique `notification_attempt(job_id,attempt_number)` continue to provide durable attempt accounting. Existing API-187 fresh source context and API-205 immediate suppression reads remain in force; accepted and uncertain provider outcomes are persisted and UNKNOWN work is reconciled without blind resend. Integration stays the sole owner of templates, dispatches and attempts. Sender, recipient, template approval, policy and retention inputs remain unconfigured; no live activation or provider qualification is claimed.
