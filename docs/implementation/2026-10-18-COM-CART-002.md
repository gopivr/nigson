Summary: Implemented private API-159 recovery eligibility backed by the existing Commerce cart/order transaction boundary. The endpoint accepts only `{}`, requires the exact Integration workload route and no signed actor, rejects query parameters, rechecks current cart eligibility under the cart row lock, and responds `no-store` with `{eligible, partyId, cartLink}`. Eligible carts create one durable `commerce.abandoned_cart_candidate` row using the table's existing unique `(cart_id, notification_key)` key and the stable `cart-recovery-v1` key. Candidate insertion and redacted audit share the local transaction; audit failure rolls the insert back. The registered `nigson.cart.commands` recovery-candidate metric increments after commit. The cart's default 24-hour eligibility time is stored in `scheduled_at`. The existing cart/checkout contracts and state transitions are unchanged.

No new migration, domain event, outbox record, or generic idempotency record was added: API-159 is a current-state eligibility read and the existing candidate uniqueness plus cart lock provide durable deduplication. The endpoint has no `If-Match`; it serializes with concurrent cart/checkout writes and evaluates current locked state. It returns a null `cartLink` because no approved link configuration exists. Eligibility does not inspect consent, expose customer contact data, mint links, send notifications, expire carts, or establish a retention/campaign policy. Integration must recheck consent independently before any separately configured send.
