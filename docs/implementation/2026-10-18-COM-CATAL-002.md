## Summary

Implemented the COM-CATAL-002 increment while preserving existing product, SKU,
catalogue and search DTOs. API-073 serves public recommendations only when the
requested market is enabled and the source product is currently published and
eligible there. Curated FEATURED/RELATED entries precede deterministic popularity
ranked from PAID/PARTIALLY_REFUNDED Commerce order lines. Every returned item is
currently published and market-eligible; there is no behavioral profiling.
API-074 requires the current, organization-unscoped SALES role, a matching enabled
market eligibility between products, and the current parent product version. It
atomically replaces the versioned Commerce recommendation rows, audits only a
changed set, and stores stable idempotent responses. No direct event or outbox
effect is specified or emitted. API-123 requires the exact `nigson-ai` workload
and `knowledge.read` route, and returns only the current published public product
projection, eligible enabled market codes and a published public image URL. Its
checksum is SHA-256 over the returned projection fields. It exposes no prices,
customer details or internal asset keys.

Public reads use the existing bounded repeatable-read catalogue path and one-second
statement timeout. Exact request fields, query parameters, recommendation limits,
role/resource/market checks, redacted audit behavior and bounded observability are
registered. Existing `commerce.product_recommendation` from DATA-001 already
contains the required invariants, so no migration or new table was needed.
