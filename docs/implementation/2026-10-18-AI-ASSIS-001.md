## Delivered

Implemented APIs 143/144/145 with AI-owned conversation, run, checkpoint, tool-invocation and feedback persistence while preserving public DTOs. No migration was needed because the required AI tables and their append-only checkpoint grants already existed. The APIs declare no direct events, so no outbox/event was added, and no cross-owner SQL was introduced.

- Conversation creation validates configured market/locale and requires a verified CUSTOMER party or creates an anonymous session protected by a signed, expiring conversation capability. Message and feedback requests recheck ownership; organization-scoped customers and staff are denied.
- Messages use exact optimistic `If-Match`, durable stable request keys, bounded per-party/anonymous rate limits, one active run per conversation and replay-safe responses. SSE responses are deterministic for replay.
- Approved `nigson-assistant` policy and prompt revisions feed the existing gateway budget reservation before model invocation. The reservation includes the prompt, user message, retrieved evidence and tool facts and is checked against the configured input cap. Calls also enforce configured output, step, tool and deadline limits.
- Public answers use only current, approved AI knowledge revisions in the configured market/locale. Sources are revalidated after generation. Injection-like requests bypass tools/model and return a safe refusal. Order/shipment/tracking requests use only the fixed read-only `get_order_status` tool, pass the verified owner party, and never fall back to public information; successful and denied attempts are persisted.
- Checkpoints use AES-GCM with conversation/run/version associated data. They are append-only, consistent with runtime grants. A known provider outage can retry with the same run and checkpoint without repeating owner tools. An uncertain accepted request stays RUNNING and reconciliation reads the provider’s existing result without blind re-invocation.
- Feedback is owner-checked, idempotent, versioned and redacts email, phone and bearer-token patterns before storage/audit. Audit entries and bounded owner/operation/outcome metrics cover create, run, tool, escalation and feedback paths.
- The deterministic stateful provider and owner-tool mocks are available only in local/test. Production does not attach them; live model invocation remains disabled unless real model capabilities and approved policy, rate, budget, retention and key/configuration inputs are supplied.
- Added generated OpenAPI operations/schemas for APIs 143–145 and aligned the shared safe problem-code vocabulary.
