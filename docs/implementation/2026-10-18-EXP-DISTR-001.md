## Implemented behavior

Experience owns APIs 092/093/094/095/172/177 and all distributor application state. Applicant submission is idempotent and checks that every attached file is applicant-owned, private, CLEAN and unlinked; required document types and notification recipient group must be explicitly configured. Review revalidates file state, checks `If-Match`, and requires an actor different from the applicant. A rejection persists locally without calling Commerce.

Approval and suspension persist their command intent and EVT-020 through the Experience transaction/outbox before the API-117 call. The stable command UUID is reused on a replay. Commerce HTTP is never called while a database transaction is active. A timeout or mismatched/out-of-order acknowledgment leaves the Experience state pending/unknown; only an exact command, organization, state and revision acknowledgment changes the application state. The explicit stateful local mock models idempotent acceptance, timeout after acceptance, and stale acknowledgment. Public DTOs remain the generated contract.

EVT-019 and EVT-020 serialize and validate through the Experience owner outbox. Generated OpenAPI exposes all six operations and their exact signed customer/staff scopes. Invalid/duplicate configured document-type values and malformed recipient group values fail configuration validation; missing values disable intake. No production business values were inferred.
