# Account wishlist

Implemented with Commerce API-216/217/218 and migration 027 (ADR-029). Account ownership is inferred from the normal authenticated session; no OTP. Product cards/detail have accessible save/remove hearts. The sidebar count and account page use persisted SKU membership. Removed disconnected ShopService saved memory state and the Session Only message. No browser storage fallback or guest merge.

The page loads current public catalogue metadata, exact saved SKU availability and current quantity-one pricing in kobo, with at most four entries resolved concurrently. Account switches/logout cancel wishlist requests and clear state. Archived/unavailable entries remain removable; transient detail/pricing failures do not become free products. Cart additions use actual SKU/product IDs, wait for the cart result before showing success and keep the saved entry. A null/failed cart result asks the user to check their cart before retrying.

Verification: npm run test:wishlist (15 tests); checkout/account regression configuration (22 tests); shop/account/shell production builds. Alternate ignored .angular/wishlist-check outputs were used because the preexisting dist/shop/browser directory is unreadable on this filesystem. Existing CSS selector warnings remain. Backend database, migration, security evidence and remaining qualification are in ../../nigson/docs/implementation/2026-11-17-WISHLIST.md.

## Activation and browser checklist

Apply backend migrations and restart/rebuild backend with make run-core in the configured Ubuntu environment. Restart frontend development servers so every remote uses the new shared-ui code. Keep backend and frontend versions together; old backend versions do not implement these endpoints.

1. Log in; save from a product card; confirm the detail heart and sidebar count agree.
2. Open Wishlist, refresh the browser, sign out/in and confirm the same item remains.
3. Use a second browser session for the same account; confirm persisted membership after loading.
4. Switch to a different account; confirm it cannot see or remove the first account's saved entries.
5. Remove from card/detail/page; refresh and confirm removal persists. Repeated clicks create no duplicates.
6. Change a real selling price through the existing admin flow; refresh Wishlist and compare to current product/cart quantity pricing.
7. Add from Wishlist to Cart; confirm actual SKU/price and that the wishlist entry remains.
8. Test an unavailable/out-of-stock item and a failed request. Removal still works; cart success is not fabricated.
9. As a guest, the heart starts login. After returning, click Save again; anonymous items are not silently persisted or merged.

No live browser/cross-device qualification or provider calls were performed for this implementation.
